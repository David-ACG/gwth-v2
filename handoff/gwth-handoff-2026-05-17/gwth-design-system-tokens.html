01
Reading this

Three layers, top to bottom.

A system is only useful if every screen built from it draws from the same well. Tokens are the well — names that don't change. Rules are how they're used. Examples are what good looks like.

01 · TOKENS

The vocabulary.

Named values for colour, type, spacing, radius, borders. Anyone building a new screen reaches for these, never raw hex or ad-hoc px. Change the value in one place; the whole system updates.

02 · RULES

The grammar.

How tokens combine. When the card surface is white and when it's a colour block. How much rust is allowed on a single page. Which heading is upright and which is italic. The felt rules made explicit.

03 · EXAMPLES

The accent.

Right-and-wrong cells showing the rule in motion. Most failures come from forgetting one rule; an example beside the rule makes that failure visible before it ships.

02

Surface, ink, block, state, chart.

05
Radius & borders

Hairlines do the work.

No shadows anywhere in the system. The cream-on-white edge plus a 1px hairline is enough lift. Radius is small — 6 px for cards, 10 px for the outer frame, full-pill only for buttons.

Component · rules

How the tokens combine.

Five rules cover most of the felt knowledge in this system. Each is paired with a right-and-wrong demo so the rule reads as a picture, not a sentence.

Rule 01

Card surface follows density: white inside the product, colour blocks on the public site.

Dense screens — dashboards, lessons, settings — hold many cards in one view. Six colour blocks at once becomes a fruit salad. Use the white-on-cream system there. The public site shows one or two cards per scroll moment; that's where colour blocks land best.

Rule 02

Rust is permanent and rare. One peak per page; everywhere else, calmer pigments.

Rust belongs to the brand: the locked logo accent, the single highest-value CTA per page, the one chart bar that demands attention, the error / blocked state. If rust shows up three times in one scroll, it stops meaning anything. Choose the moment.
Permitted usesPer page · max 1 of each
Brand markPeak CTAChart-2 barError / blocked
Never more than four rust touches in any single scroll. Never rust for an info pill, a button border, or decorative emphasis.
Rule 03

Sage is for passive; forest is for active.

Both are green. Sage (warm olive-grey) is the colour of *what is, at rest* — a streak count, a baseline data row, a passive metadata pill. Forest (vegetal green) is the colour of *what was completed* — a verified credential, a finished module, today's active step.

Rule 04

Italic display is reserved for editorial moments.

Italic Source Serif 4 is the system's voice. Page openers, pull quotes, takeaways, marketing headlines. Card titles, widget labels, settings rows — those stay upright. If everything is italic, nothing reads as the special moment.

Rule 05

Four buttons, in strict order.

One primary per surface. Secondaries can multiply. Ghost links are for tertiary moves. Rust-filled is reserved for the single peak CTA — almost always on the public site. Inside the product, primary is always ink, never rust.

Rule 06

Credentials don't expire. Scores decay.

A GWTH credential is never revoked or invalidated by time. Instead, the score drops as the curriculum updates and the learner falls behind — gently, predictably, recoverably. Three implications for design: never use the word expired; always show the current score next to the peak; and the visual treatment shifts from forest (active) to amber (needs refresh), never to rust (rust means broken).
